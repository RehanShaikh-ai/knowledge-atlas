# v0.3.1 Infrastructure Architecture

**Release:** v0.3.1 — Semantic Retrieval & AI Foundation
**Workstream:** C — Infrastructure, Database & Integration
**Contract:** `docs/contracts/CONTRACT_v0.3.1.md`

---

## Overview

v0.3.1 adds a vector store (Qdrant), job queue (Redis + ARQ), and Git-based versioning to the existing PostgreSQL + FastAPI stack. This document covers the infrastructure-layer changes owned by Workstream C.

---

## New Services (Docker Compose)

### Qdrant — Vector Store

```yaml
image: qdrant/qdrant:v1.9.1
ports: 6333:6333
volumes: qdrant_data:/qdrant/storage
```

Stores embeddings and payload-filtered retrieval metadata. One collection per workspace, named `{QDRANT_COLLECTION_PREFIX}_{workspace_id}` (contract §7.1). No user PII stored — only workspace/note/chunk UUIDs.

The application handles Qdrant unavailability at startup via retry-with-backoff rather than a hard Compose `depends_on` health check, per §16.4.

### Redis — ARQ Job Queue Transport

```yaml
image: redis:7-alpine
ports: 6379:6379
```

Used exclusively as the ARQ job transport (§4 data boundaries). No persistent application data is stored in Redis. Redis outages affect background indexing only — the HTTP API remains available.

### Worker — ARQ Background Job Processor

```yaml
command: uv run arq backend.app.jobs.worker.WorkerSettings
depends_on: [redis, postgres]
volumes: git_repositories:/data/workspaces
```

Runs the ARQ worker loop. Separated from the HTTP backend so indexing jobs do not block API requests. Both `backend` and `worker` share the same Docker image and the `git_repositories` volume mount.

## New Volumes

| Volume | Name | Purpose |
|---|---|---|
| `postgres_data` | `knowledge_atlas_postgres_data` | Existing — PostgreSQL WAL and data files |
| `qdrant_data` | `knowledge_atlas_qdrant_data` | Qdrant vector index storage |
| `git_repositories` | `knowledge_atlas_git_repositories` | Git-versioned Markdown note content |

### Git Volume Detail (§16.2)

Mounted at `/data/workspaces` inside both `backend` and `worker`. `GIT_REPOSITORY_ROOT=/data/workspaces` in `.env`.

Repository layout within the volume (§11.2):
```
/data/workspaces/
└── {workspace_id}/
    └── repository/
        └── {note_id}.md
```

Path components are UUIDs only — no user-supplied strings, no note titles. Path construction uses `pathlib.Path.resolve()` with a traversal check (`GIT_PATH_INVALID` on failure).

## Database Schema — New Tables (Migration 0004)

Four tables added by `backend/alembic/versions/0004_create_semantic_retrieval_tables.py`. No existing table is modified.

### `note_versions` (§6.1)

Tracks every Git snapshot of a note. `commit_hash` (String 40) links to the Git SHA-1. `is_ai_edit` distinguishes human vs AI-originated commits for the approval flow (§11.4).

| Column | Type | Notes |
|---|---|---|
| `id` | UUID PK | SQLAlchemy-generated |
| `note_id` | UUID FK | → `notes.id` CASCADE |
| `workspace_id` | UUID FK | → `workspaces.id` CASCADE (denormalized) |
| `commit_hash` | String(40) | Git SHA-1 |
| `author_id` | UUID FK | → `users.id` RESTRICT |
| `message` | String(500) | nullable |
| `is_ai_edit` | Boolean | false for human edits |
| `created_at` | DateTime(UTC) | immutable |

Unique: `(note_id, commit_hash)`.
Index: `idx_note_versions_note_id` on `(note_id, created_at DESC)`.

### `note_chunks` (§6.2)

One row per text chunk per version. `id` doubles as the Qdrant point ID (§7.2) — no separate identifier. `content_hash` (SHA-256, 64 hex chars) enables idempotent reindexing (§7.5).

| Column | Type | Notes |
|---|---|---|
| `id` | UUID PK | Also Qdrant `chunk_id` |
| `note_id` | UUID FK | → `notes.id` CASCADE |
| `version_id` | UUID FK | → `note_versions.id` CASCADE |
| `workspace_id` | UUID FK | → `workspaces.id` CASCADE (denormalized) |
| `chunk_index` | Integer | 0-based, order-preserving |
| `content` | Text | Raw chunk text |
| `content_hash` | String(64) | SHA-256 hex |
| `token_count` | Integer | At time of chunking |
| `embedding_model` | String(100) | e.g. `BAAI/bge-small-en-v1.5` |
| `embedding_dimension` | Integer | Must match Qdrant collection |
| `created_at` | DateTime(UTC) | immutable |

Unique: `(version_id, chunk_index)`.
Indexes: `idx_note_chunks_version_id`, `idx_note_chunks_note_id`.

### `index_jobs` (§6.3)

ARQ job lifecycle state. `id` is also the ARQ job key. `note_ids` JSONB is null for full-workspace reindex, or a list of UUIDs for targeted reindex.

| Column | Type | Notes |
|---|---|---|
| `id` | UUID PK | Also ARQ job key |
| `workspace_id` | UUID FK | → `workspaces.id` CASCADE |
| `job_type` | String(50) | `index_workspace` / `index_note` |
| `status` | String(20) | `queued` / `running` / `completed` / `failed` |
| `note_ids` | JSONB | null = full workspace |
| `retry_count` | Integer | default 0 |
| `max_retries` | Integer | from `JOB_MAX_RETRIES` |
| `enqueued_at` | DateTime(UTC) | immutable |
| `started_at` | DateTime(UTC) | nullable |
| `completed_at` | DateTime(UTC) | nullable |
| `error_message` | Text | sanitized — no paths or stack traces |

Index: `idx_index_jobs_workspace_status` on `(workspace_id, status)`.

### `saved_searches` (§6.4)

Named, saved query per workspace.

| Column | Type | Notes |
|---|---|---|
| `id` | UUID PK | SQLAlchemy-generated |
| `workspace_id` | UUID FK | → `workspaces.id` CASCADE |
| `name` | String(150) | display name |
| `query` | String(500) | saved query text |
| `search_mode` | String(20) | `semantic` / `lexical` / `hybrid` |
| `created_at` | DateTime(UTC) | immutable |

Index: `idx_saved_searches_workspace` on `workspace_id`.

## CI Changes (§20.3)

The `docker-compose-validate` job in `.github/workflows/ci.yml` now validates:
- `qdrant` service present with `qdrant/qdrant` image
- `redis` service present
- `worker` service present, depends on `redis` + `postgres`
- `git_repositories` and `qdrant_data` volumes declared
- `backend` mounts `git_repositories`

The `alembic-migrations-check` job now asserts `head == 0004` and fails hard if migrations are missing (previously only warned).

## What Workstream C Does Not Own

Per §3.3, the following are explicitly Workstream B (backend/AI) responsibilities:
- `backend/app/services/` — embedding, chunking, vector, retrieval, RAG, LLM, git, job, version, activity, saved_search services
- `backend/app/api/v1/` — all new API routes
- `backend/app/jobs/worker.py` — ARQ worker settings and job function implementations
- `backend/tests/` — backend unit tests

Workstream C provides the infrastructure scaffolding those services depend on.
