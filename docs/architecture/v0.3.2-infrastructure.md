# v0.3.2 Infrastructure Architecture

**Release:** v0.3.2 — Knowledge Graph & GraphRAG  
**Workstream:** C — Infrastructure, Database & Integration  
**Contract:** `docs/contracts/CONTRACT_v0.3.2.md`  

---

## Overview

v0.3.2 introduces the Knowledge Graph and GraphRAG engine on top of the v0.3.1 infrastructure foundation. No new infrastructure services or Docker containers are introduced. The release extends:
1. **PostgreSQL Schema**: Adds 6 new tables for entities, relationships, provenance, clusters, and link suggestions.
2. **Qdrant Vector Payload**: Adds `entity_ids` and `cluster_id` metadata fields to existing chunk vectors without introducing new collections.
3. **ARQ / Redis Background Jobs**: Extends queue processing for entity extraction, relationship extraction, and clustering jobs.

## Database Migration (`0005_create_knowledge_graph_tables.py`)

A single, fully reversible Alembic revision (`0005`) extends the schema with 6 tables in strict foreign-key dependency order:

### Tables Created

1. **`note_clusters`**: Semantic cluster definitions per workspace.
2. **`graph_entities`**: Extracted or human-created concepts, persons, technologies, etc. Enforces unique `(workspace_id, name)` and `entity_type` enum constraint (`concept`, `person`, `technology`, `project`, `place`, `event`, `unknown`).
3. **`graph_relationships`**: Directed typed relationships between entities with confidence score and `is_manual` protection. Enforces unique `(workspace_id, source_entity_id, target_entity_id, relationship_type)`.
4. **`entity_chunks`**: Fine-grained provenance mapping extracted entities and relationships back to source chunks and notes. Enforces unique `(entity_id, chunk_id)`.
5. **`note_cluster_members`**: Membership association table linking notes to clusters with composite primary key `(cluster_id, note_id)` and membership score.
6. **`link_suggestions`**: AI-generated note-to-note link suggestions awaiting human approval. Enforces unique `(workspace_id, source_note_id, target_note_id)` and status check constraint (`pending`, `accepted`, `rejected`).

### Required Indexes (§6.7)

- `idx_entities_workspace_name` on `graph_entities(workspace_id, name)`
- `idx_entities_workspace_type` on `graph_entities(workspace_id, entity_type)`
- `idx_entities_cluster` on `graph_entities(cluster_id)`
- `idx_relationships_workspace` on `graph_relationships(workspace_id)`
- `idx_relationships_source` on `graph_relationships(source_entity_id)`
- `idx_relationships_target` on `graph_relationships(target_entity_id)`
- `idx_entity_chunks_entity` on `entity_chunks(entity_id)`
- `idx_entity_chunks_chunk` on `entity_chunks(chunk_id)`
- `idx_entity_chunks_note` on `entity_chunks(note_id)`
- `idx_cluster_members_note` on `note_cluster_members(note_id)`
- `idx_link_suggestions_workspace_status` on `link_suggestions(workspace_id, status)`
- `idx_link_suggestions_source` on `link_suggestions(source_note_id)`

### Reversibility

`downgrade()` cleanly drops all 6 tables and their indexes in reverse FK dependency order (`link_suggestions` → `note_cluster_members` → `entity_chunks` → `graph_relationships` → `graph_entities` → `note_clusters`), restoring the schema to revision `0004` without touching any v0.1.x–v0.3.1 tables.
